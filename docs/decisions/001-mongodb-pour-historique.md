# 001. 閲覧履歴を MongoDB に保存する

- 日付：2026-09（Issue #1 で決定。正確な日付は〈要確認〉）
- 状態：採用（CDA の授業の進み方によって見直す可能性あり）
- 判断した人：ユーザー
- DWWM 版との関係：新規（CDA 版で追加する Épic 9）
- 関連する授業：あり（学習記録を `docs/learning/` に追加したらリンクする）

## 背景

ログインしているユーザーが見たレシピを、すべて履歴として残したい（US 9.1、US 9.2）。同じレシピを何度見ても、そのたびに新しい記録を作る。

## 検討した選択肢

1. MySQL に履歴テーブルを作る
2. MongoDB にコレクションを作る

MySQL との比較は検討済み。詳しい長所・短所は、授業の学習記録を追加するときに書き足す。

## 決定

MongoDB の `viewHistory` コレクションに保存する（`src/Document/ViewHistory.php`：userId、recipeId、viewedAt）。

## 理由

Issue #1 に書かれた理由：書き込みが速いこと（制約のチェックがない）。本番環境で増え続けるコレクションに向いていること。

## 影響

- MySQL と MongoDB の2つのデータベースを扱う構成になる。
- `ViewHistory` は userId と recipeId を整数で持つ。MySQL の User や Recipe との関係は、データベースでは保証されない。

## CDA の能力との対応

- CP7 リレーショナル DB の設計と構築（MySQL との使い分け）
- CP8 SQL／NoSQL のデータアクセスコンポーネント
